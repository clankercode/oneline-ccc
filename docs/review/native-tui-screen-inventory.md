## Navigation semantics relevant to the report

1. **Horizontal tabs and screen controls share one flat focus list.** `internal/tui/controls.go:14` prepends Dashboard/Models/Review/Jobs at indices 0–3 on every screen; body controls follow. `view.go:26-35` renders those four entries horizontally; `view.go:229-232` omits them from the body. `input.go:46-61` makes Tab/Shift+Tab wrap over the entire list and Up/Down clamp over that same list, including unavailable controls. There is no main-screen Left/Right or F6 handler (`input.go:26-79`). This is not a directional tab/content focus model.
2. **Exact repeated-Down path from startup:** `New` starts Dashboard with zero-valued focus (`model.go:56-58`). Inspection preserves logical focus (`async.go:15,78-79`). Four Down presses traverse Dashboard → Models → Review → Jobs → first body control; with clients present that is the first client row (`controls.go:19-36`). Moving across tabs changes focus only: screen switching requires Enter (`input.go:68-69,93-95`). Conversely, activating any tab calls `goTo`, which jumps to body index 4 (`model.go:139`). Thus the number of Down presses depends on the starting focus, not simply the active tab.
3. **Arrow selection and Tab focus differ.** Up/Down calls `selectFocused`, changing selected client when focus lands on a client (`input.go:54-61,82-85`); Tab does not (`input.go:46-53`). Enter on a client selects it and opens Models; Space selects it and stages management (`input.go:70-77,97-100`). On the wide Dashboard, the logical order is all client rows then right-column actions, despite adjacent visual columns (`dashboard.go:33-42`). Browser arrows are scoped to client rows and wrap within filtered clients (`site/tui-preview.js:53-57,147-155`), a concrete behavioral difference from native clamped whole-screen traversal.
4. **Modal/editor keys use different movement rules.** Confirmation choices toggle with Tab/Shift+Tab/Left/Right; Up/Down does not choose (`commands.go:94-105`). Palette uses Up/Down/Tab/Shift+Tab with clamped results (`commands.go:54-59`); Help uses Up/Down/PgUp/PgDown, with Enter/? closing (`commands.go:43-50`). Key entry uses Tab/Shift+Tab across four controls; other editors consume Tab and keep focus (`editor.go:45-53`), while Left/Right edits the caret (`editor.go:76-80`). The generic shell footer still says Tab move/Enter act except in editors and palette (`view.go:41-47`). Inventory these control contexts separately.
5. **Secondary screens depend on command search.** All ten screen destinations are in the native catalog (`commands.go:15-16`), but only four are top tabs. Settings also exposes Utilities and Service (`controls.go:113-114`); Gateway/Repair/SSH/Settings have no corresponding dedicated top-level control. Catalog Apply is intentionally absent (`commands.go:11-12`); exact Apply exists only in Review (`controls.go:72-84`).
6. **Back retains data but resets navigation position.** Esc on Review returns `previous` when set; Esc elsewhere returns Dashboard; Dashboard Esc does nothing (`input.go:37-45`). Explicit review Back defaults to Models if previous is unset, while other Back controls go Dashboard (`input.go:188-194`). Every `goTo` resets focus to 4 and scroll to -1 (`model.go:139`), rather than restoring the prior row/action/scroll position promised by `docs/design/tui-screen-flows.md:25`. Modal dismissal separately restores the saved control ID (`model.go:140-152`).
7. **Global/filter/quit boundaries matter.** `/` opens a filter editor on any non-editor/non-modal screen and its save does not navigate to Dashboard (`input.go:20-32`; `editor.go:107-111`), unlike browser Filter, which first opens Dashboard (`site/tui-preview.js:84`). `Ctrl+C` clears editor/closes modal and then requests safe quit (`input.go:13-18`); cancellation may therefore first open a confirmation even though catalog labels Ctrl+C as Request cancellation (`commands.go:22`). Jobs has a direct cancellation action (`input.go:203-207`). Ordinary `q` is literal text in editors/palette and is not the universal modal-close key.

## Shared native states and additional comparison surfaces

- **Shell:** screen/modal/editor breadcrumb, active section versus focused tab, public status, working status, fixed key footer, one focused control versus persistent selected client, unavailable reason versus Review `[locked]`, and long wrapped control labels. Source: `internal/tui/view.go:17-72,130-152`; `theme.go:47-57`. Disabled controls remain navigable; activating them reports the reason (`input.go:87-90`).
- **Asynchronous work:** initial inspection/loading, refresh with drafts retained, busy-action refusal, Plan, Apply, Discover, credential save, Service, Repair, command preparation, cancellation requested/waiting, timeout/refusal/failure, final receipt/reconciliation. These are shell/body states, not separate screens: `internal/tui/model.go:56-58,178-203`; `async.go:11-125`; `input.go:102-104,203-207`; `commands.go:109-115`. The browser uses synchronous in-memory simulation and has no comparable live-operation/recovery presentation (`site/tui-state.mjs:64-85,96-99`).
- **Responsive layout and scrolling:** five documented/test-source sizes 120x40, 100x30, 80x24, 60x20, 40x12 (`docs/design/tui-screen-flows.md:221-228`; `internal/tui/layout_test.go:38-56`, read only). Native's implemented structural breakpoint is Dashboard width >=100; other screens use `screenRows` at all widths (`dashboard.go:10-11`; `layout.go:19-23`). Below 40 columns or 12 rows the native view only disables AltScreen and still uses its frame (`view.go:48-72`); do not label it the documented guided fallback. Include auto-follow, manual PgUp/PgDown, pinned offscreen focus, small-height clipping, resize/reflow, and long Unicode IDs (`layout.go:25-45`; `view.go:48-69`; `input.go:62-67`; `panels.go:23-30`). Browser wide/compact/narrow are CSS presentation modes, not terminal-cell proof (`site/tui-preview.css:101-119`; `docs/design/tui-visual-system.md:68-72`).
- **Appearance:** dark/light/mono, NoColor, focused/selected/unavailable labels, semantic success/warning/failure words, and paired terminal foreground/background (`internal/tui/view.go:73-128`; `theme.go:8-45`). ASCII and ReducedMotion checkbox states exist, but the inspected renderer does not branch on them. Browser theme controls cover three palettes, not NoColor/native terminal behavior.
- **Handoff/return:** Launch and confirmed SSH suspend TUI ownership via `tea.Exec`, can fail before child launch, and restore the shell with a return status (`internal/tui/async.go:17-24,122-123`; `runner.go:9-25`). Repair Export similarly leaves the body to print a redacted brief to terminal scrollback and returns with success/failure status (`security.go:49-63`; `model.go:75-80`). These native boundaries lack browser counterparts.
- **First-run/rerun/client detail are states, not extra implemented screen names.** Source currently expresses them through Dashboard/Models/Gateway, optional monitor controls, and imported/empty/error inspection states. The design's first-run wizard, dedicated client detail, rich job stages/recovery page, SSH admin screens, utility installer, or agent-repair execution should not be counted as existing native screens (`internal/tui/commands.go:15`; compare text-only design at `docs/design/tui-screen-flows.md:39-74,95-114,151-217`).
